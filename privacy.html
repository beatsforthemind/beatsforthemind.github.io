Application and owner

Wallace Personal is Eric Anderson’s local-first, single-owner assistant. Its application and private runtime run on the owner’s Mac. It supports development, research, planning, and continuity across user-selected AI clients through the Model Context Protocol (MCP).

The personal Google connections are bound to the owner’s personal Google account. They are separate from work integrations. This public website supplies application and consent information; it does not sign visitors into Google or display account contents.

Google data and permissions

Google consent is requested separately for Gmail and Google Calendar. Wallace requests read-only access and offline renewal so it can continue bounded collection without a sign-in at every session. Google may still require renewed authorization after revocation or other account and provider changes.

Gmail

The https://www.googleapis.com/auth/gmail.readonly permission allows reading Gmail messages and settings. Wallace’s actual collection is narrower: it verifies the personal account and reads one page of at most thirty Inbox message headers and previews from the preceding fourteen days. This includes sender headers, subject, dates, message and thread identifiers, Inbox/unread labels, and a short preview when provided. Stored observations include the subject, preview, sender, received time, unread state, and a Gmail source link. Wallace does not make bulk copies of historical mailbox contents.

Requested message bodies are fetched fresh from Google. Each fetch verifies the personal owner and current bounded Inbox coverage again, then returns up to 8,000 characters of inline plain-text content for the active request. Wallace does not persist the result in a raw-body cache. It does not import attachments or HTML message bodies, send mail, modify labels, mark messages read, or delete messages.

Google Calendar

The https://www.googleapis.com/auth/calendar.readonly permission allows reading accessible calendars and events. Wallace initially selects only the owner’s primary calendar. Additional calendars require an explicit local selection.

A calendar view covers one day in the past and fourteen days ahead. It reads calendar identity and timezone, titles, descriptions, start and end times, all-day dates, status, availability, event type, update timestamps, and source links when provided. Recurring events are expanded into instances. Reads are bounded to three pages of 100 events per selected calendar and 500 events overall. Wallace does not create, edit, invite attendees to, or delete events.

Permission is broader than collection. These Google permissions permit more reading than Wallace’s current Inbox and selected-calendar windows. Incomplete pages, truncated bodies, and stale reads are reported as limited coverage. Missing items are not treated as completed work, deleted email, or canceled events.

How data is used

Google data supports recent personal communication context, meeting preparation, availability, private plans, and requested reminders or summaries. Collection detects changes deterministically. Wallace makes no background calls to AI model APIs.

Personal Google observations, requested message content, and deliberately saved personal summaries remain in the personal domain. Work-scoped retrieval cannot access personal titles, message text, appointment details, or source links. Work-facing planning may use aggregate personal busy intervals to reduce available capacity without disclosing those details.

Wallace does not sell Google data, use it for advertising, or use it to train general-purpose AI models. Wallace’s use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including Limited Use requirements.

AI clients and sharing

The local application supplies context to AI clients the owner chooses, such as Claude, ChatGPT, Cursor, or a coding extension. During an active personal or private-owner session, requested Google context may be returned through MCP to that client and its selected model provider. This can include the personal message or calendar details needed for the owner’s request.

Those clients and providers process received content under their own privacy policies, account settings, retention practices, and terms. The owner must review those settings and use Google-derived context only with clients and providers that exclude it from general-purpose model training. Wallace does not control a provider’s settings or guarantee its practices. Content returned to a remote AI client is no longer exclusively local.

Wallace does not automatically send Google contents to a model in the background. Its public consent site receives no private account data. No public data feed or multi-user account service is provided.

Storage and security

Credentials, OAuth registrations, refresh grants, and connection selections are stored in an encrypted, Git-ignored project vault. The vault uses authenticated AES-256-GCM encryption. The owner can use a recovery passphrase; an optional macOS Keychain entry holds only an automatic-unlock key.

Personal observations, memory, inbox items, and plans are stored in a local SQLite database under owner-only filesystem permissions. The commissioned Mac uses FileVault to encrypt its underlying volume. This is volume encryption, rather than separate encryption inside SQLite. Backups and portable exports have their own encryption. The security of the Mac, its user account, and any authorized client remains part of protecting the information.

Only the local daemon writes private state. Account checks, fixed read operations, result bounds, profile permissions, and secret redaction limit access. OAuth and vault management use a protected local operator interface, not model-accessible credential tools.

Retention and deletion

Requested Gmail bodies are transient tool results, not persistent raw-body cache entries. Collected Inbox previews, calendar events, and related inbox records remain in local observation storage until the integration is disconnected; the collection windows limit new reads, not the lifetime of those stored records. These are timestamped observations, not permanent live views of the source.

The owner can deliberately save useful summaries, decisions, or plans into personal memory. That user-directed memory is separate from automatic source collection and persists until corrected, forgotten, or removed by the owner.

Disconnecting a Google integration removes its saved grant, observations, and inbox items, and clears any associated raw cache. It stops further collection. Deliberately saved Google-derived memory is handled separately: the owner must forget those records when they also want those summaries removed. Revoking Google authorization stops future access but does not itself delete local records.

Encrypted database backups omit the raw-content cache. Automatic backup retention keeps the latest backup for each of seven daily dates and four weekly periods. Previously stored observations, inbox records, and durable memory can remain in those snapshots until retention removes them. Owner-created portable exports remain until the owner deletes them. Deleting live records does not rewrite existing backup snapshots or exports.

Copies already shared with a selected AI client or provider follow that recipient’s deletion and retention controls. Wallace cannot erase those copies through a local forget operation.

Your controls

  • Review Google’s read permissions before consenting, and authorize only the intended personal account.
  • Disable collection or disconnect an integration using Wallace’s local operator controls.
  • Remove Wallace’s access in your Google Account to revoke its authorization.
  • Use Wallace’s forget control for deliberately saved memory, and delete retained backups or exports when necessary.
  • Choose which AI clients receive personal context and review their privacy settings.

For help with a privacy or deletion request, contact the maintainer below. Wallace is a personal installation rather than a public account service.

This website

This is a static informational website. It uses no analytics scripts, cookies, forms, account login, or Google API requests. Fonts and artwork are served with the site. Following an external link takes you to that service’s own site and policies.

The website’s hosting provider may process ordinary request information, such as IP addresses and server access logs, under its own policies. That hosting does not include Wallace’s personal application database or Google connection credentials.
